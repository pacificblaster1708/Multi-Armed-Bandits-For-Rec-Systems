Algorithm

Five Bandits,
One Winner

We implement and benchmark five multi-armed bandit strategies. Diag-LinUCB — the paper's core contribution — dominates across all metrics by combining sparse graph structure with O(1) diagonal updates.

Diag-LinUCB ⭐
Primary Algorithm · DeepMind Paper
Production Ready

Diagonal approximation of LinUCB's covariance matrix. Instead of maintaining a full d×d matrix per arm, only the diagonal d_j is kept — collapsing update cost to O(1) and memory to O(d·C). Paired with a sparse bipartite graph that routes users through cluster centroids, enabling fully distributed parameter updates with no item-level synchronization.

// UCB Score — Eq. 7 from Yi et al. 2023
UCB_j(u) = Σc ∈ supp(w_u) w_{u,c} · b_{j,c} / d_{j,c}
             + α · √( Σc ∈ supp(w_u) w²{u,c} / d_{j,c} )

// Diagonal Update — Eq. 8
d_{j,c} ← d_{j,c} + w²{u,c}
b_{j,c} ← b_{j,c} + w_{u,c} · r_{u,j}

System Design

Offline + Online
Hybrid Pipeline

The system runs in two phases: an offline stage that builds the sparse bipartite graph once at startup, and an online stage that updates bandit parameters in real time on every Spotify interaction.

01
Offline — Graph Construction
Two-Tower Embedding + K-Means

User and song feature vectors are projected into a shared embedding space. K-Means clusters the user embeddings into C=20 centroids. For each cluster, the top-W songs by dot-product similarity become its candidate set.

sklearn · kmeans · cosine similarity
02
Offline — Graph Construction
Sparse Bipartite Graph G(U, V, E)

Algorithm 2 from the paper: build G where left nodes are user clusters and right nodes are candidate songs. Edges encode (cluster, song) pairs worth exploring — massively pruning the search space from 200 songs × all users to ~W songs per cluster.

scipy sparse · ~4M edges
03
Online — Real-time Scoring
Softmax Cluster Assignment + UCB Scoring

At query time, the user's Spotify preference vector (tempo, energy, valence, genre) is mapped to K=5 nearest clusters with softmax weights w_{u,c}. Candidate songs from those clusters are scored by Eq. 8 — exploitation term plus α-weighted exploration bonus.

FastAPI · τ=0.3 · α=1.0 default
04
Online — Closed-Loop Learning
Feedback → Parameter Update → WebSocket

Like / skip / play / complete events fire POST /feedback. The aggregation processor updates d_{j,c} ← d_{j,c} + w²_{u,c} and b_{j,c} ← b_{j,c} + w_{u,c}·r_{u,j} in-memory with O(1) cost. Updated metrics are broadcast over WebSocket to the live dashboard instantly.

aiosqlite · WebSocket · SQLite

Implementation

The Core Algorithm
in Python

The Diag-LinUCB update loop — 30 lines that replace a full matrix inversion with scalar ops.

bandits.py — DiagLinUCB.update() Python 3.11 
def score(self, song_id: str, user_weights: dict) -> float:
    """Compute UCB score for a (song, user) pair — Eq. 8."""
    exploit_term = 0.0
    explore_term = 0.0

    for cluster_id, w_uc in user_weights.items():
        if cluster_id not in self.b[song_id]:
            # New edge → infinite UCB (prioritised exploration)
            return float('inf')

        b_jc = self.b[song_id][cluster_id]   # reward numerator
        d_jc = self.d[song_id][cluster_id]   # diagonal covariance

        exploit_term += w_uc * b_jc / d_jc
        explore_term += (w_uc ** 2) / d_jc

    return exploit_term + self.alpha * (explore_term ** 0.5)


def update(self, song_id: str, user_weights: dict, reward: float):
    """O(K) update — no matrix inversion needed. Eq. 7."""
    for cluster_id, w_uc in user_weights.items():
        if cluster_id not in self.d[song_id]:
            self.d[song_id][cluster_id] = 1.0   # init diagonal to I
            self.b[song_id][cluster_id] = 0.0   # init mean to 0

        # Diagonal update — replaces full A_j ← A_j + x·xᵀ
        self.d[song_id][cluster_id] += w_uc ** 2

        # Mean vector update — b_j ← b_j + w_uc · r_{u,j}
        self.b[song_id][cluster_id] += w_uc * reward

    self.n_updates += 1
